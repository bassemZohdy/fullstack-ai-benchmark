# Getting Started

## 1. Validate Tools

```bash
./scripts/test-setup.sh --harness opencode --provider z-ai --auto-approve true --retries 3
```

This validates the directory layout, OpenCode availability, prompt templates, cartridges, and GLM generation.

## 2. Run GLM Workflow Validation

```bash
./scripts/run-benchmark.sh \
  --model GLM-5.1Z.AI \
  --level overview \
  --backend spring-boot \
  --frontend angular \
  --provider z-ai
```

Validation output:

```text
WORKSPACE/opencode-glm-5.1/overview/
RESULTS/opencode-glm-5.1/spring-boot-angular/overview/evaluation-results.json
```

## 3. Run Additional Benchmarks

After validation works, run benchmarks with different models and stacks using OpenRouter:

```bash
export OPENROUTER_API_KEY="your-key"
./scripts/run-benchmark.sh --model kimi/2.6 --level overview --backend spring-boot --frontend angular --provider openrouter
```

The current evaluator is implemented for Spring Boot plus Angular. Use other backend/frontend pairs only when you want to generate workspaces for later evaluation support.

## Notes

- OpenCode is the harness for all current runs.
- OpenCode is invoked in non-interactive script mode with `opencode run`.
- Model arguments are passed to OpenCode as `provider/model`.
- `--auto-approve true` passes OpenCode's `--dangerously-skip-permissions` flag so generation can write files without interactive prompts.
- `--retries <count>` controls generation retry attempts.
- OpenCode session ids are persisted in `WORKSPACE/opencode-<model-slug>/<level>/.opencode-session-id` and reused with `opencode run --session <id>` when available. Detailed retry metadata is written to `WORKSPACE/opencode-<model-slug>/<level>/.opencode-session`.
- Built-in levels are `overview` and `detailed`.
- Active level workspaces are cleared before generation; `.opencode-session-id` is preserved, `.opencode-session` is refreshed, and `README.md` is generated by OpenCode itself.
- The root project intentionally has no `package.json`.
- `WORKSPACE/opencode-<model-slug>/<level>/` stores one active project per model and spec level so `overview` and `detailed` can be compared side by side.
- `RESULTS/` stores permanent benchmark outputs.
- All four selectors are required: `--model`, `--level`, `--backend`, and `--frontend`.

## Troubleshooting

**OpenCode CLI not found**

Install and configure OpenCode, then rerun:

```bash
opencode --version
```

**OPENROUTER_API_KEY not set**

Only required for `--provider openrouter`:

```bash
export OPENROUTER_API_KEY="your-key"
```
