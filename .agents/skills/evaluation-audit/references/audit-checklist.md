# Audit Checklist

Use this checklist when scores need source-level review.

## Inputs

- `WORKSPACE/<harness>-<model-slug>/<level>/`
- `RESULTS/<harness>-<model-slug>/<backend>-<frontend>/<level>/static-evaluation.json`
- `RESULTS/<harness>-<model-slug>/<backend>-<frontend>/<level>/e2e-execution.json`
- `RESULTS/<harness>-<model-slug>/<backend>-<frontend>/<level>/evaluation-results.json`
- `PROMPTS/cartridges/backend/<backend>.md`
- `PROMPTS/cartridges/frontend/<frontend>.md`

## Audit Order

1. Confirm runtime status first.
   - If E2E is `build_failed`, `docker_failed`, `health_failed`, or `error`, the project is not deployable regardless of static score.
2. Inspect failed static checks.
   - Verify each failed test against real files and file contents.
3. Check cartridge alignment.
   - If the evaluator requires something the cartridge does not require, treat that as an evaluator issue.
4. Check layout assumptions.
   - Look for combined YAML manifests, standalone Angular bootstraps, folder-based Spring conventions, and environment files outside the narrowest expected path.
5. Patch evaluator logic, not result JSON.
6. Add a regression smoke test before trusting the fix.
7. Rerun evaluation and compare old vs new scores.

## Common False-Negative Patterns

- Spring services or repositories detected only by filename instead of annotations or package structure
- Angular standalone apps penalized for lacking `app.module.ts`
- Runtime environment config missed because it uses `src/assets/env.js`, `proxy.conf.json`, or local `.env`
- Kubernetes `Service` or `Ingress` objects embedded in broader manifest files
- Optional wrappers or tooling treated as required

## Expected Outputs

- A concrete list of evaluator issues with file evidence
- Patched `EVAL/` logic if needed
- Regression coverage in `scripts/test-regressions.sh`
- Rescored benchmark JSON generated by scripts
